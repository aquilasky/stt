# LectureCaption 手工测试清单

> 适用范围：无法由自动化测试可靠覆盖的 macOS 权限、真实音频、窗口交互、长时间运行与外部网络场景。
> 执行人：项目用户或其明确委托的测试者。
> 主代理职责：提供可复现的步骤、审阅结果、修复失败项并重新安排回归测试。

## 1. 执行规则

- 每个用例只能记录为“通过”、“失败”或“阻塞”；未执行不等同于通过。
- “失败”必须记录实际输出、发生时间和复现步骤；不要粘贴 API Key、完整授权令牌或课堂敏感内容。
- 系统权限修改、管理员认证、真实课堂音频播放和 60 分钟运行由执行人操作，主代理不代替执行。
- 一个 Feature 的所有标记为“必测”的用例通过后，才能完成对应 Feature、将 Draft PR 转为 Ready 或开始下一个 Feature。

## 2. 记录模板

在 PR 的 `Manual validation` 区域按下面格式记录每个用例：

```text
MAN-XXX: 通过 | 失败 | 阻塞
设备与系统：<Mac 型号 / macOS 版本>
输入：<实际输入或音频来源>
实际输出：<观察到的界面与行为>
备注：<失败信息、截图路径或复现条件；不得包含密钥>
```

## 3. 启动测试 App

1. 在 Finder 或 Xcode 中打开 `LectureCaption.xcodeproj`。
2. 在 Scheme 菜单选择 `LectureCaption`，运行目标选择“我的 Mac”。
3. 按 Command-R 构建并启动 Debug App。
4. 在开始 MAN-001 前，记录 Mac 型号、macOS 版本、输入设备和当前是否已授权麦克风。

命令行构建仅用于确认项目可编译，不能代替实际 App 测试：

```bash
xcodebuild -project LectureCaption.xcodeproj \
  -scheme LectureCaption \
  -destination 'platform=macOS,arch=arm64' \
  build
```

## 4. Stage 1：音频采集与本地待机

### MAN-000 启动并显示主窗口（必测）

前置条件：`LectureCaption` 未运行；已在 Xcode 中选择 `LectureCaption` Scheme 和“我的 Mac”运行目标。

操作：按 Command-R，等待构建和启动完成。

输入：无。

预期输出：

- `LectureCaption` 进程保持运行，并显示一个标题为“LectureCaption”的主窗口。
- 主窗口包含会话设置和“等待字幕”预览区域，窗口位于任一已连接显示器的可见区域。
- 不应只出现 Dock 图标、空白窗口或立即退出。

### MAN-001 麦克风权限状态与请求（必测）

前置条件：打开刚构建的 `LectureCaption.app`；系统设置中未授权或已撤销该 App 的麦克风权限。

操作：

1. 点击工具栏“开始”。
2. 在 macOS 提示框选择“允许”，或选择“不允许”。
3. 若选择“不允许”，在系统设置的“隐私与安全性 > 麦克风”中手动恢复授权，再回到应用点击“开始”。

输入：选择“允许”或“不允许”之一。

预期输出：

- 首次点击“开始”时由 macOS 显示麦克风授权提示。
- 允许后会话进入“本地监听”，顶部 dBFS 数值开始刷新。
- 拒绝后应用显示“未获得麦克风权限。”错误提示，不崩溃，不开始采集。

### MAN-002 麦克风实时采集与停止（必测）

前置条件：MAN-001 已授权。

操作：

1. 点击“开始”，正常说话 5 秒，然后保持安静 3 秒。
2. 观察顶部 dBFS 数值和“本地监听/检测到输入”状态。
3. 点击“结束”。

输入：正常人声与静音。

预期输出：

- 说话时 dBFS 相比静音明显升高，状态在约 200 ms 后变为“检测到输入”。
- 静音后约 600 ms，状态恢复“本地监听”。
- 点击“结束”后会话状态为已结束，dBFS 不再持续刷新；再次点击“开始”可重新采集且不崩溃。

### MAN-003 手动暂停不被声音解除（必测）

前置条件：麦克风正在采集且显示“检测到输入”。

操作：点击“暂停”，然后持续说话 5 秒，再点击“继续”。

输入：持续人声。

预期输出：

- 暂停期间会话保持“手动暂停”，不会因声音自动变为识别中。
- 点击“继续”后返回“本地监听”；再次检测到声音时可恢复输入活动。

### MAN-004 自动待机与恢复（必测）

前置条件：自动待机选择“15 秒”，麦克风正在采集。

操作：

1. 先说话 2 秒以激活本地活动检测。
2. 保持静音至少 16 秒。
3. 再说话 2 秒。

输入：人声、至少 16 秒静音、再次人声。

预期输出：

- 静音达到阈值后，状态变为“自动待机”。
- 再次说话时约 200 ms 后恢复本地活动；不需要重新点击“开始”。
- 后续 Stage 2 接入云端后，需额外验证预滚 PCM 不漏首音节。

### MAN-005 连续运行 60 分钟（必测）

前置条件：已验证的麦克风采集正在运行；Activity Monitor 可用。

操作：

1. 点击“开始”，持续播放课程音频或保持正常课堂环境 60 分钟。
2. 在第 0、10、20、30、40、50、60 分钟记录 Activity Monitor 中 `LectureCaption` 的内存和 CPU。
3. 期间至少执行一次静音到自动待机、一次恢复声音、一次结束并重新开始。

输入：不少于 60 分钟的连续真实音频，包含至少一次静音区间。

预期输出：

- 应用不崩溃、不假死，开始/结束/重新开始均有效。
- 内存不会持续单调增长；CPU 没有持续异常占用。
- 本地活动、自动待机和恢复行为与 MAN-004 一致。

记录附加字段：各时间点内存、CPU、麦克风设备与任何异常。

### MAN-006 Dock 与任务视图激活（必测）

前置条件：`LectureCaption` 未运行；当前桌面至少有一个其他应用窗口。

操作：

1. 在当前桌面中按 Command-R 启动 `LectureCaption`。
2. 观察 Dock 是否出现 `LectureCaption` 图标，并确认主窗口位于当前桌面且获得焦点。
3. 切换到另一个应用，再点击 Dock 中的 `LectureCaption` 图标。
4. 打开任务视图，选择 `LectureCaption` 主窗口。
5. 切换到另一个桌面，再回到 `LectureCaption` 所在桌面；重复一次从 Dock 激活应用。
6. 结束应用，确认 Dock 图标随进程退出而消失。

输入：Command-R、Dock 图标点击和任务视图中的主窗口点击。

预期输出：

- 应用运行时 Dock 显示 `LectureCaption` 图标。
- 从 Dock 或任务视图选择窗口后，窗口在当前桌面前置并获得键盘焦点。
- 桌面切换不会把主窗口移动到其他桌面或使其无故落后于同一桌面的其他窗口；从 Dock 激活后主窗口重新前置并获得键盘焦点。
- 不会因启动、桌面切换或激活而创建或切换到新的桌面。

## 5. 后续 Feature 手工测试

### MAN-100 阿里云实时原文与密钥存储（必测）

前置条件：阿里云百炼已开通实时语音识别；已取得有效的 Workspace ID 和 DashScope API Key；已确认 Workspace 所在地域（新加坡或北京）；麦克风权限已授予。

操作：

1. 在“阿里云识别”中填写 Workspace ID 和 API Key，选择与 Workspace 匹配的“地域”（新加坡或北京），选择“阿里云实时”，点击“开始”。
2. 正常说一段至少 10 秒的英文或中文，包含一个术语表中的词；中途停顿 2 秒后继续说话。
3. 点击“结束”，再次点击“开始”，但不重新填写 API Key，再说一段短句。

输入：有效 Workspace ID、有效 API Key、至少两段自然语音和一个术语表词。

预期输出：

- 首次有效输入后状态短暂显示“正在连接”，收到服务端响应后显示“正在识别”。
- 原文预览中先出现较浅的临时文本，断句后更新为稳定文本；已确认文本不再跳动或重复。
- 点击“开始”后 API Key 输入框立即清空并写入本机 `LocalCredentials.json`；第二次开始不重新输入 API Key 仍能连接，且 API Key 不出现在错误提示、日志或预览中。
- 结束后不再产生新字幕；已有字幕保留在预览中。

### MAN-101 阿里云实时错误与自动待机（必测）

前置条件：MAN-100 已通过；麦克风正在采集，自动待机选择“15 秒”。

操作：

1. 开始会话，说话 2 秒后保持静音至少 16 秒，再说话 2 秒。
2. 停止会话，将 Workspace ID 改为无效值，再开始并说话。

输入：有效识别会话中的静音恢复；无效 Workspace ID。

预期输出：

- 静音阈值后界面变为“自动待机”，不再继续发送云端音频；再次说话后自动重新连接并恢复字幕。
- 使用无效 Workspace ID、错误地域或无效 API Key 时，界面显示“阿里云 WebSocket 连接失败”，并提示检查 API Key、Workspace ID 和地域；不得显示 API Key。
- 无效配置时显示清晰的连接或鉴权错误，应用不崩溃；已有字幕不丢失，麦克风本地监听仍可结束。

### MAN-200 DeepSeek 实时翻译与术语上下文（必测）

前置条件：阿里云实时原文识别可用；具有有效 DeepSeek API Key；课程名称填写 `Machine Learning`，主题填写 `Optimization`，术语表包含 `learning rate=学习率`。

操作：

1. 在“DeepSeek 翻译”填写 API Key，点击“开始”。
2. 说出 `The learning rate controls the size of each optimization step.`，等待阿里云提交最终原文和译文出现。
3. 连续说出两条可断句的英文句子，观察两条译文的显示顺序。
4. 点击“结束”，重新打开应用但不重新输入 DeepSeek API Key，开始新的会话并说出一句英文。

输入：有效 DeepSeek API Key、三条英文短句和一个术语表词。

预期输出：

- 已确认的原文通常在 1 至 2 秒内出现对应简体中文译文；临时原文不触发翻译。
- 第一条译文保留并遵守 `learning rate=学习率`；后续原文到达不会清掉已经显示的译文。
- 连续句子的译文按原文顺序写回对应行，不会交换或覆盖。
- DeepSeek API Key 在点击“开始”后清空并保存到本机配置；重启后无需重填仍可翻译，且 Key 不出现在字幕、提示或日志中。

### MAN-201 DeepSeek 翻译失败不阻断原文（必测）

前置条件：阿里云实时原文识别可用；DeepSeek API Key 为空、无效或已被临时撤销。

操作：开始会话并连续说出两条可断句英文句子。

输入：无效或缺失的 DeepSeek API Key、两条英文短句。

预期输出：

- 原文仍连续显示并保持已确认字幕不跳动、不丢失。
- 缺失 Key 时只显示原文，不弹出重复错误；无效 Key 或网络失败时对应句子可缺少译文，但后续原文仍继续出现。
- 点击暂停、结束、自动待机和恢复仍与 MAN-101 一致。

### MAN-300 主界面、字号与本地课堂记录（必测）

前置条件：MAN-100 已通过；已产生至少 8 条已确认字幕，其中至少 2 条具有译文。

操作：

1. 在主窗口字幕区向上滚动至第一条，再向下滚动回最新一条。
2. 在工具栏点击“减小字幕字号”（`A-`）两次，再点击“增大字幕字号”（`A+`）四次。
3. 在工具栏“更多”菜单打开“课程与识别配置”，确认可修改课程名称和术语表；点击“完成”关闭。
4. 点击工具栏“保存记录”，随后点击“结束”。
5. 在“更多 > 本地课堂记录”中打开刚保存的会话，进入详情并核对首条、末条原文与已有译文。
6. 退出并重新启动应用，再次打开“本地课堂记录”复查同一会话。
7. 保持主窗口显示状态，连续产生三条字幕，观察视图是否始终跟随到最新原文和最后出现的译文。

输入：至少 8 条已确认原文，至少 2 条已完成译文，以及课程名称和主题。

预期输出：

- 所有字幕可通过滚动查看，首条不会因后续字幕到达而丢失；文本可选择复制。
- 每次点击字号按钮均立即生效，原文和译文不重叠、不截断主工作区；大字号仍可滚动阅读完整内容。
- 课程与识别配置不常驻主窗口，关闭后主字幕区占满工作区。
- 保存或结束后，记录列表显示课程名、主题和开始时间；详情中的字幕数量、顺序、原文和已有译文与本次会话一致。
- 重启后记录仍存在；API Key 不出现在记录标题、详情或本地字幕内容中。
- 连续字幕和译文到达时，主记录区自动保持在底部；不会停留在旧记录位置。

记录附加字段：会话字幕总数、保存后详情字幕总数、重启后详情字幕总数、任一不一致的首末文本。

### MAN-301 主窗口聚焦字幕流（必测）

前置条件：MAN-100 已通过；主窗口处于正常大小，已开始会话。准备至少 6 条可断句的短句、1 条会换行的长句和其中一条的中文译文。

操作：

1. 连续输入至少 6 条短句，观察每一条成为最新字幕时的滚动和字号变化。
2. 输入一条会在当前窗口宽度下换行的长句，等待该句的译文返回。
3. 使用 `A-` 和 `A+` 各两次，再连续输入两条短句。
4. 在字幕区手动向上滚动查看旧字幕，然后向下滚动；继续产生一条新字幕。

输入：6 条以上短句、1 条长句、至少 1 条迟到返回的译文，以及字号调整操作。

预期输出：

- 正在识别时，上一条已确认断句居中对齐并明显放大；即使同时出现多条临时识别文本，它们也全部位于确认文本下方。没有已确认断句时，临时文本正常显示且不被放大。
- 已确认的历史字幕保持正常大小和清晰度，可阅读和选择复制；不出现阶梯式淡化。
- 临时原文新增或修订时以短暂的淡入和轻微上移动画更新，不突然跳出；新断句到达时视图以平滑的单次动画将阅读焦点移到该断句，不出现明显跳动、闪白或持续来回滚动。
- 临时原文确认、长原文和迟到译文到达后，当前已确认行均重新保持居中；长原文和译文自动换行且居中显示，不截断、不重叠，也不会把视图拉离当前行。
- 当前字幕下方保留明显空白，阅读不会紧贴窗口底边；调整字号后该空白、居中对齐与自动跟随均继续生效。
- 手动查看旧内容后，新字幕到达时自动回到最新聚焦行。

记录附加字段：窗口尺寸、字号、是否观察到跳动或截断、长句原文和译文是否完整显示。

### MAN-202 连续上下文翻译润色（必测）

前置条件：MAN-200 已通过；DeepSeek API Key 有效；原文语言为英语、译文语言为简体中文。

操作：连续说出或播放三句有指代关系的英文，示例：`We define the objective function. It measures the total error. Then we minimize it.`

输入：三句连续、语义相关的英语短句。

预期输出：

- 三句原文仍逐句保留为 STT 最终结果，不会被 DeepSeek 改写。
- 后两句译文可根据前句对 `It`、`it` 等指代做自然处理，语义与原文一致，不凭空添加课程事实。
- 翻译按原文顺序写回；任一条翻译失败时，后续原文和翻译仍继续。

### MAN-203 结束后新会话仍可翻译（必测）

前置条件：MAN-200 已通过；阿里云实时原文识别与 DeepSeek 翻译均已配置且可用；原文语言为英语、译文语言为简体中文。

操作：

1. 点击“开始”，说出一条可断句的英文，例如 `The first session should be translated.`，等待原文和中文译文显示。
2. 点击“结束”，等待会话状态变为已结束。
3. 不重填任何 API Key，立即再次点击“开始”。
4. 说出另一条可断句的英文，例如 `The second session should also be translated.`，等待原文和中文译文显示。
5. 对照第二次会话的字幕区域，确认第一条会话的原文或译文没有写入其中。

输入：两次独立会话各一条可断句的英文；第二次开始前不修改 DeepSeek API Key。

预期输出：

- 两次会话都能显示各自已确认原文对应的简体中文译文。
- 第二次会话不要求重新填写或保存 DeepSeek API Key。
- 第一会话的延迟译文不会出现在第二会话的任何字幕行；第二会话译文只写回其对应原文。

记录附加字段：两次会话的原文、对应译文、从第二次点击“开始”到译文出现的大致耗时，以及是否出现跨会话字幕。

### MAN-400 悬浮字幕窗口（必测）

前置条件：MAN-200 已通过；主窗口已有至少 4 条已确认字幕，其中至少 2 条已有译文；另有一条临时原文。准备一条足以换行的长句。

操作：

1. 在主窗口工具栏启用“悬浮字幕”，切换到浏览器、播放器或会议应用，输入文字到该应用中。
2. 拖动悬浮窗到屏幕另一位置，并从任意边缘调整为较窄、再较宽的尺寸；切换到另一个桌面或全屏应用后返回。
3. 让一条长原文或译文显示在浮窗中，依次点击字号减小和增大按钮；观察窗口边界和文本布局。
4. 鼠标移入窗口，使用直接显示的按钮切换双语、仅原文和仅译文模式，并使用背景不透明度加减按钮调整背景；鼠标移出后等待控制条隐藏。
5. 点击悬浮窗内关闭按钮，再次从主窗口启用悬浮字幕。

输入：至少 4 条已确认字幕、2 条译文、1 条临时原文、1 条长文本；跨桌面或全屏应用的窗口切换。

预期输出：

- 字幕窗在主窗口失焦后仍位于课程应用之上，不会抢占当前应用的键盘输入焦点。
- 字幕窗可拖动和缩放，在其他桌面和全屏应用上仍可见；默认显示最新 3 条与当前模式匹配的字幕。
- 双语模式显示原文在上、译文在下；仅原文和仅译文模式分别只显示对应文字；临时原文颜色明显更浅。
- 长文本在浮窗宽度内自动换行，不显示省略号；字体改变后窗口保持有限矩形尺寸、可见黑色背景和字幕内容，不变成长条或空白无限黑框。
- 控制条只在鼠标移入时出现且固定在右上角，所有控件均为直接可点击的按钮，不出现二级菜单；控制条不挤压、遮挡或随正文/字号移动。关闭后浮窗立即消失，主窗口开关同步关闭，重新启用后显示当前字幕。

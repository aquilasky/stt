# LectureCaption 手工测试清单

> 适用范围：无法由自动化测试可靠覆盖的 macOS 权限、真实音频、窗口交互、长时间运行与外部网络场景。
> 执行人：项目用户或其明确委托的测试者。
> 主代理职责：提供可复现的步骤、审阅结果、修复失败项并重新安排回归测试。

## 1. 执行规则

- 每个用例只能记录为“通过”、“失败”或“阻塞”；未执行不等同于通过。
- “失败”必须记录实际输出、发生时间和复现步骤；不要粘贴 API Key、完整授权令牌或课堂敏感内容。
- 系统权限修改、管理员认证、真实课堂音频播放和 60 分钟运行由执行人操作，主代理不代替执行。
- 一个 Feature 的所有标记为“必测”的用例通过后，才能完成对应 Feature、将 Draft PR 转为 Ready 或开始下一个 Feature。

## 2. 记录模板

在 PR 的 `Manual validation` 区域按下面格式记录每个用例：

```text
MAN-XXX: 通过 | 失败 | 阻塞
设备与系统：<Mac 型号 / macOS 版本>
输入：<实际输入或音频来源>
实际输出：<观察到的界面与行为>
备注：<失败信息、截图路径或复现条件；不得包含密钥>
```

## 3. 启动测试 App

1. 在 Finder 或 Xcode 中打开 `LectureCaption.xcodeproj`。
2. 在 Scheme 菜单选择 `LectureCaption`，运行目标选择“我的 Mac”。
3. 首次本机构建前，运行 `./Scripts/setup-local-signing.sh`，确认登录钥匙串中存在 `LectureCaption Stable Local Signing`。
4. 按 Command-R 构建并启动 Debug App。
5. 在开始 MAN-001 前，记录 Mac 型号、macOS 版本、输入设备和当前是否已授权麦克风/系统音频。
6. 如果本次构建首次使用本地签名，先在“录屏与系统音频”中关闭并重新打开 `LectureCaption` 授权，再返回 App。

命令行构建仅用于确认项目可编译，不能代替实际 App 测试：

```bash
xcodebuild -project LectureCaption.xcodeproj \
  -scheme LectureCaption \
  -destination 'platform=macOS,arch=arm64' \
  build
```

## 4. Stage 1：音频采集与本地待机

### MAN-000 启动并显示主窗口（必测）

前置条件：`LectureCaption` 未运行；已在 Xcode 中选择 `LectureCaption` Scheme 和“我的 Mac”运行目标。

操作：按 Command-R，等待构建和启动完成。

输入：无。

预期输出：

- `LectureCaption` 进程保持运行，并显示一个标题为“LectureCaption”的主窗口。
- 主窗口包含会话设置和“等待字幕”预览区域，窗口位于任一已连接显示器的可见区域。
- 不应只出现 Dock 图标、空白窗口或立即退出。

### MAN-001 麦克风权限状态与请求（必测）

前置条件：打开刚构建的 `LectureCaption.app`；系统设置中未授权或已撤销该 App 的麦克风权限。

操作：

1. 在“权限”区域确认“麦克风”状态。
2. 点击工具栏“开始”。
3. 在 macOS 提示框选择“允许”，或选择“不允许”后点击麦克风权限行的齿轮按钮打开系统设置。
4. 返回应用并观察权限状态。

输入：选择“允许”或“不允许”之一。

预期输出：

- 未授权时显示“未请求”“已拒绝”或“受系统限制”，且齿轮按钮可打开“隐私与安全性 > 麦克风”。
- 允许后重新回到 App，状态显示“已授权”。
- 拒绝后应用显示清晰的错误提示，不崩溃，不开始采集。

### MAN-002 麦克风实时采集与停止（必测）

前置条件：MAN-001 已授权；输入选择“麦克风”。

操作：

1. 点击“开始”，正常说话 5 秒，然后保持安静 3 秒。
2. 观察顶部 dBFS 数值和“本地监听/检测到输入”状态。
3. 点击“结束”。

输入：正常人声与静音。

预期输出：

- 说话时 dBFS 相比静音明显升高，状态在约 200 ms 后变为“检测到输入”。
- 静音后约 600 ms，状态恢复“本地监听”。
- 点击“结束”后会话状态为已结束，dBFS 不再持续刷新；再次点击“开始”可重新采集且不崩溃。

### MAN-003 手动暂停不被声音解除（必测）

前置条件：麦克风正在采集且显示“检测到输入”。

操作：点击“暂停”，然后持续说话 5 秒，再点击“继续”。

输入：持续人声。

预期输出：

- 暂停期间会话保持“手动暂停”，不会因声音自动变为识别中。
- 点击“继续”后返回“本地监听”；再次检测到声音时可恢复输入活动。

### MAN-004 自动待机与恢复（必测）

前置条件：自动待机选择“15 秒”，麦克风正在采集。

操作：

1. 先说话 2 秒以激活本地活动检测。
2. 保持静音至少 16 秒。
3. 再说话 2 秒。

输入：人声、至少 16 秒静音、再次人声。

预期输出：

- 静音达到阈值后，状态变为“自动待机”。
- 再次说话时约 200 ms 后恢复本地活动；不需要重新点击“开始”。
- 后续 Stage 2 接入云端后，需额外验证预滚 PCM 不漏首音节。

### MAN-005 系统音频权限入口（必测）

前置条件：系统设置中未授权或已撤销该 App 的“录屏与系统录音”权限。

操作：

1. 启动 App，保持输入为“麦克风”。
2. 确认启动期间没有弹出系统音频授权流程。
3. 切换输入为“系统音频”，点击系统音频权限行的锁形“请求授权”按钮；系统弹窗出现时选择允许。
4. 若系统未显示弹窗，点击齿轮按钮进入“录屏与系统音频”，完成对 `LectureCaption` 的授权后返回 App。
5. 返回 App 后等待约 1 秒，或点击“刷新应用列表”。

输入：系统音频权限拒绝与允许两种情况。

预期输出：

- 麦克风模式启动不会请求系统音频权限。
- 未授权时“系统音频”显示“需要在系统设置授权”，齿轮按钮打开对应系统设置页面。
- 授权后状态显示“已授权”，刷新后可展示可选择的运行中应用。
- 新构建切换到本地签名后，必须对 `LectureCaption` 重新授权；不要复用旧的同名未签名进程授权记录。
- 若仍未授权，App 会显示 `ScreenCaptureKit` 的错误域和代码；记录该完整提示用于缺陷定位。

### MAN-006 选定应用的系统音频采集（必测）

前置条件：MAN-005 已授权；打开两个可发声应用 A 与 B，例如 Safari 视频和音乐播放器；其中只有 A 播放声音。

操作：

1. 在 App 中选择“系统音频”，刷新应用列表并选择 A。
2. 点击“开始”，播放 A 的声音 5 秒，再静音 A。
3. 保持 A 静音，仅播放 B 的声音 5 秒。
4. 点击“结束”。

输入：A 有声/B 静音；A 静音/B 有声。

预期输出：

- 选择 A 前“开始”不可用；选择 A 后可启动。
- A 播放时 dBFS 与本地活动状态有变化；低音量内容也应在系统音频检测基础 `+20 dB` 增益后被检测到。该增益不修改待发送 PCM，正常内容不得产生持续失真或假活动。
- A 静音、仅 B 播放时输入应保持静音或显著低于 A 播放时，不能采集 B 的声音。
- 结束后不再采集；A 退出后刷新列表，A 不再可选。

### MAN-007 连续运行 60 分钟（必测）

前置条件：麦克风或 MAN-006 已验证的系统音频正在采集；Activity Monitor 可用。

操作：

1. 点击“开始”，持续播放课程音频或保持正常课堂环境 60 分钟。
2. 在第 0、10、20、30、40、50、60 分钟记录 Activity Monitor 中 `LectureCaption` 的内存和 CPU。
3. 期间至少执行一次静音到自动待机、一次恢复声音、一次结束并重新开始。

输入：不少于 60 分钟的连续真实音频，包含至少一次静音区间。

预期输出：

- 应用不崩溃、不假死，开始/结束/重新开始均有效。
- 内存不会持续单调增长；CPU 没有持续异常占用。
- 本地活动、自动待机和恢复行为与 MAN-004 一致。

记录附加字段：各时间点内存、CPU、输入来源、耳机/扬声器状态与任何异常。

# LectureCaption 手工测试清单

> 适用范围：无法由自动化测试可靠覆盖的 macOS 权限、真实音频、窗口交互、长时间运行与外部网络场景。
> 执行人：项目用户或其明确委托的测试者。
> 主代理职责：提供可复现的步骤、审阅结果、修复失败项并重新安排回归测试。

## 1. 执行规则

- 每个用例只能记录为“通过”、“失败”或“阻塞”；未执行不等同于通过。
- “失败”必须记录实际输出、发生时间和复现步骤；不要粘贴 API Key、完整授权令牌或课堂敏感内容。
- 系统权限修改、管理员认证、真实课堂音频播放和 60 分钟运行由执行人操作，主代理不代替执行。
- 一个 Feature 的所有标记为“必测”的用例通过后，才能完成对应 Feature、将 Draft PR 转为 Ready 或开始下一个 Feature。

## 2. 记录模板

在 PR 的 `Manual validation` 区域按下面格式记录每个用例：

```text
MAN-XXX: 通过 | 失败 | 阻塞
设备与系统：<Mac 型号 / macOS 版本>
输入：<实际输入或音频来源>
实际输出：<观察到的界面与行为>
备注：<失败信息、截图路径或复现条件；不得包含密钥>
```

## 3. 启动测试 App

1. 在 Finder 或 Xcode 中打开 `LectureCaption.xcodeproj`。
2. 在 Scheme 菜单选择 `LectureCaption`，运行目标选择“我的 Mac”。
3. 按 Command-R 构建并启动 Debug App。
4. 在开始 MAN-001 前，记录 Mac 型号、macOS 版本、输入设备和当前是否已授权麦克风。

命令行构建仅用于确认项目可编译，不能代替实际 App 测试：

```bash
xcodebuild -project LectureCaption.xcodeproj \
  -scheme LectureCaption \
  -destination 'platform=macOS,arch=arm64' \
  build
```

## 4. Stage 1：音频采集与本地待机

### MAN-000 启动并显示主窗口（必测）

前置条件：`LectureCaption` 未运行；已在 Xcode 中选择 `LectureCaption` Scheme 和“我的 Mac”运行目标。

操作：按 Command-R，等待构建和启动完成。

输入：无。

预期输出：

- `LectureCaption` 进程保持运行，并显示一个标题为“LectureCaption”的主窗口。
- 主窗口包含会话设置和“等待字幕”预览区域，窗口位于任一已连接显示器的可见区域。
- 不应只出现 Dock 图标、空白窗口或立即退出。

### MAN-001 麦克风权限状态与请求（必测）

前置条件：打开刚构建的 `LectureCaption.app`；系统设置中未授权或已撤销该 App 的麦克风权限。

操作：

1. 点击工具栏“开始”。
2. 在 macOS 提示框选择“允许”，或选择“不允许”。
3. 若选择“不允许”，在系统设置的“隐私与安全性 > 麦克风”中手动恢复授权，再回到应用点击“开始”。

输入：选择“允许”或“不允许”之一。

预期输出：

- 首次点击“开始”时由 macOS 显示麦克风授权提示。
- 允许后会话进入“本地监听”，顶部 dBFS 数值开始刷新。
- 拒绝后应用显示“未获得麦克风权限。”错误提示，不崩溃，不开始采集。

### MAN-002 麦克风实时采集与停止（必测）

前置条件：MAN-001 已授权。

操作：

1. 点击“开始”，正常说话 5 秒，然后保持安静 3 秒。
2. 观察顶部 dBFS 数值和“本地监听/检测到输入”状态。
3. 点击“结束”。

输入：正常人声与静音。

预期输出：

- 说话时 dBFS 相比静音明显升高，状态在约 200 ms 后变为“检测到输入”。
- 静音后约 600 ms，状态恢复“本地监听”。
- 点击“结束”后会话状态为已结束，dBFS 不再持续刷新；再次点击“开始”可重新采集且不崩溃。

### MAN-003 手动暂停不被声音解除（必测）

前置条件：麦克风正在采集且显示“检测到输入”。

操作：点击“暂停”，然后持续说话 5 秒，再点击“继续”。

输入：持续人声。

预期输出：

- 暂停期间会话保持“手动暂停”，不会因声音自动变为识别中。
- 点击“继续”后返回“本地监听”；再次检测到声音时可恢复输入活动。

### MAN-004 自动待机与恢复（必测）

前置条件：自动待机选择“15 秒”，麦克风正在采集。

操作：

1. 先说话 2 秒以激活本地活动检测。
2. 保持静音至少 16 秒。
3. 再说话 2 秒。

输入：人声、至少 16 秒静音、再次人声。

预期输出：

- 静音达到阈值后，状态变为“自动待机”。
- 再次说话时约 200 ms 后恢复本地活动；不需要重新点击“开始”。
- 后续 Stage 2 接入云端后，需额外验证预滚 PCM 不漏首音节。

### MAN-005 连续运行 60 分钟（必测）

前置条件：已验证的麦克风采集正在运行；Activity Monitor 可用。

操作：

1. 点击“开始”，持续播放课程音频或保持正常课堂环境 60 分钟。
2. 在第 0、10、20、30、40、50、60 分钟记录 Activity Monitor 中 `LectureCaption` 的内存和 CPU。
3. 期间至少执行一次静音到自动待机、一次恢复声音、一次结束并重新开始。

输入：不少于 60 分钟的连续真实音频，包含至少一次静音区间。

预期输出：

- 应用不崩溃、不假死，开始/结束/重新开始均有效。
- 内存不会持续单调增长；CPU 没有持续异常占用。
- 本地活动、自动待机和恢复行为与 MAN-004 一致。

记录附加字段：各时间点内存、CPU、麦克风设备与任何异常。

### MAN-006 Dock 与任务视图激活（必测）

前置条件：`LectureCaption` 未运行；当前桌面至少有一个其他应用窗口。

操作：

1. 在当前桌面中按 Command-R 启动 `LectureCaption`。
2. 观察 Dock 是否出现 `LectureCaption` 图标，并确认主窗口位于当前桌面且获得焦点。
3. 切换到另一个应用，再点击 Dock 中的 `LectureCaption` 图标。
4. 打开任务视图，选择 `LectureCaption` 主窗口。
5. 切换到另一个桌面，再回到 `LectureCaption` 所在桌面；重复一次从 Dock 激活应用。
6. 结束应用，确认 Dock 图标随进程退出而消失。

输入：Command-R、Dock 图标点击和任务视图中的主窗口点击。

预期输出：

- 应用运行时 Dock 显示 `LectureCaption` 图标。
- 从 Dock 或任务视图选择窗口后，窗口在当前桌面前置并获得键盘焦点。
- 桌面切换不会把主窗口移动到其他桌面或使其无故落后于同一桌面的其他窗口；从 Dock 激活后主窗口重新前置并获得键盘焦点。
- 不会因启动、桌面切换或激活而创建或切换到新的桌面。

## 5. 后续 Feature 手工测试

### MAN-600 连续课堂时间轴与句级时间戳（必测）

前置条件：有效的阿里云 Workspace ID 和 API Key 已配置；麦克风权限已授予；自动待机选择“15 秒”。

操作：

1. 点击“开始”，说出两句各约 3 秒的完整句子，中间停顿 1 秒，观察每条实时字幕左侧的时间。
2. 保持静音至少 16 秒，确认进入“自动待机”，然后再说出一句完整句子，观察恢复后的时间。
3. 点击“结束”，打开“本地课堂记录”，进入刚保存的记录，逐条比对其时间与实时字幕中的时间。

输入：三句自然语音，句间 1 秒停顿，以及至少 16 秒静音。

预期输出：

- 每条字幕显示本地 `HH:mm:ss`；同一句在识别中更新为最终文本时，开始时间不跳动。
- 三条字幕的时间按课堂实际经过时间单调递增；自动待机恢复后的第三条时间不会回到课堂开头、倒退或与前一条重叠。
- 历史详情中同一条字幕显示的 `HH:mm:ss` 与实时界面完全一致。
- 历史列表和详情标题为 `Wed_19_Aug_26_18:07` 格式，末尾时间使用 24 小时制。
- 原文内容、字幕顺序、临时/已确认状态与未显示时间戳时的既有行为一致。

记录附加字段：三条实时时间、自动待机恢复后的时间、历史详情对应时间，以及是否发生时间倒退或跳跃。

### MAN-601 网络恢复后的预滚与时间连续性（必测）

前置条件：MAN-600 的有效阿里云配置仍在；Mac 已连接网络；麦克风权限已授予；可通过关闭并重新开启 Wi-Fi 造成短暂断网。

操作：

1. 点击“开始”，连续说话并确认至少有一条带时间的实时字幕。
2. 在不停止说话的情况下关闭 Wi-Fi，等待应用显示连接错误或回到本地监听状态。
3. 重新开启 Wi-Fi，继续说话至少 5 秒，等待识别恢复，再结束课堂并进入刚保存的历史详情。

输入：有效配置、连续自然语音、一次短暂网络中断与恢复。

预期输出：

- 网络中断期间应用不崩溃，已有字幕保留，错误提示中不包含 API Key。
- 网络恢复后无需重新点击“开始”即可继续出现字幕；恢复起点不应丢失首个明显音节。
- 恢复后的实时 `HH:mm:ss` 不早于中断前的最后一条时间；历史详情中的对应时间与实时界面一致。

记录附加字段：断网前最后时间、恢复后第一条时间、是否漏掉首音节、错误提示及历史详情对应时间。

### MAN-602 时间戳显示开关（必测）

前置条件：已有一条包含至少一条字幕的本地课堂记录；开始新的有效识别会话并产生至少一条实时字幕；已打开悬浮字幕。

操作：

1. 确认主窗口、悬浮字幕和历史详情中的字幕均显示 `HH:mm:ss`。
2. 点击主窗口工具栏的时钟图标，确认图标状态改变。
3. 观察主窗口和悬浮字幕，再打开本地课堂记录详情。
4. 再次点击时钟图标恢复显示，并重复查看三处字幕。

输入：至少一条实时字幕和一条已保存字幕，以及工具栏时钟图标点击两次。

预期输出：

- 默认显示时间戳；隐藏后主窗口、悬浮字幕和历史详情均不显示 `HH:mm:ss`。
- 恢复后原有时间戳立即返回，三个表面显示相同的时间。
- 两次切换均不清除或改变原文、译文、字幕顺序和历史记录。

记录附加字段：隐藏和恢复后每个表面的显示结果，以及任一内容或顺序变化。

### MAN-603 历史记录 TXT / JSON 导出（必测）

前置条件：已有一条至少含两条字幕的本地课堂记录，其中一条带中文译文，另一条不带译文；原文中包含中文、引号、换行或反斜杠中的至少一种字符。

操作：

1. 打开“本地课堂记录”，进入该记录详情。确认右上角有格式选择、时钟开关和导出按钮。
2. 选择 TXT，保持时钟开关开启，点击导出并在 Finder 保存；使用文本编辑器打开文件。
3. 关闭时钟开关，重复导出 TXT 并检查内容。
4. 依次在时钟开关开启和关闭时选择 JSON 并导出；用文本编辑器或 JSON 检查工具打开两个文件。
5. 返回历史记录界面，重新打开原记录，确认其字幕顺序、原文和译文未变化。

输入：同一条有效本地记录，TXT/JSON 各导出一次带时间戳和一次不带时间戳，共四个文件。

预期输出：

- 系统显示保存面板；TXT 和 JSON 均以 UTF-8 保存并可正常打开。
- TXT 按历史详情字幕顺序输出双语内容；开启时每条存在的原文或译文以 `[HH:mm:ss]` 开头，关闭时无该前缀。
- JSON 包含 `formatVersion`、`course`、`topic` 和按顺序排列的 `segments`；开启时包含会话和字幕时间字段，关闭时不包含任何时间字段。
- 引号、换行、反斜杠、中文和空译文不损坏 JSON，也不改变 TXT 的字幕顺序；导出文件中不包含 API Key、本机路径或内部错误信息。
- 导出不修改原课堂记录。

记录附加字段：四个保存文件名、每个格式/开关组合的打开结果、特殊字符结果，以及原记录是否保持不变。

### MAN-604 配置与历史记录直接入口（必测）

前置条件：应用处于实时字幕主窗口；至少存在一条本地课堂记录。

操作：

1. 检查主窗口工具栏，定位悬浮字幕、时间戳、课程与识别配置、本地课堂记录、字号调整等控件。
2. 直接点击课程与识别配置图标，确认配置窗口打开；关闭后回到主窗口。
3. 直接点击本地课堂记录图标，确认列表打开；点击左上角返回箭头回到实时字幕。
4. 再次打开本地课堂记录，进入任意一条记录详情，点击左上角返回箭头回到列表，再点击列表左上角返回箭头回到实时字幕。

输入：工具栏的配置图标、历史记录图标，以及历史列表和详情页的左上角返回按钮。

预期输出：

- 配置和历史记录入口均与悬浮字幕、时间戳和字号控件处于工具栏同一层级，不需要先打开“更多”或其他二级菜单。
- 两个入口均可直接打开对应界面，且不改变当前字幕、时间戳显示状态或采集状态。
- 历史列表退出和历史详情返回均使用左上角返回箭头；详情先返回列表，列表再返回实时字幕。

记录附加字段：两个直接入口是否可见、每次返回后的目标页面，以及任一状态丢失或错误。

### MAN-605 主窗口原生全屏（必测）

前置条件：主窗口已打开；已有至少一条本地课堂记录；悬浮字幕已开启并显示至少一条字幕。若测试采集状态，需已配置有效 API 并处于识别中或本地监听中。

操作：

1. 使用主窗口左上角绿色窗口按钮进入全屏，观察主窗口和悬浮字幕；再次点击绿色按钮退出。
2. 从 macOS 菜单栏的“显示”菜单中选择“进入全屏”，再选择“退出全屏”。
3. 使用 `Control-Command-F` 进入和退出全屏。
4. 在全屏期间打开本地课堂记录，进入并返回一条详情；若正在采集，确认状态栏、音量与新字幕继续更新。
5. 在主窗口全屏时切换到其他桌面或全屏应用后再返回，确认悬浮字幕和主窗口状态。

输入：绿色窗口按钮、显示菜单、`Control-Command-F`；至少一条历史记录和一条悬浮字幕，且可选地包含一段进行中的识别。

预期输出：

- 三种系统原生入口均可平滑进入和退出主窗口全屏，无需应用自定义全屏按钮。
- 全屏往返不清除实时字幕、历史记录、时间戳显示设置、悬浮字幕状态或当前采集状态。
- 历史记录列表和详情在全屏下正常显示与返回；识别中的字幕和状态持续更新。
- 悬浮字幕仍位于主窗口全屏内容之上，不抢占当前应用键盘焦点，退出全屏后位置和尺寸不改变。

记录附加字段：三种入口各自结果、采集是否连续、悬浮字幕在全屏及跨桌面后的可见性、任一状态丢失或窗口异常。

### MAN-606 防止系统自动息屏（必测）

前置条件：主窗口已打开；在“系统设置 - 锁定屏幕”中将当前供电状态的“关闭显示器”空闲时间临时设为一个短且可观察的值，例如 1 分钟。确保测试期间不触摸键盘、触控板或鼠标；测试结束后恢复自己的系统设置。

操作：

1. 确认主窗口工具栏的显示器图标默认未启用，且未开始或已结束采集。
2. 点击显示器图标使其启用，停止所有输入，等待超过设置的显示器空闲时间，再观察屏幕状态。
3. 再次点击显示器图标关闭，停止所有输入并等待超过同一空闲时间，确认系统恢复默认显示器息屏行为。
4. 重复快速开启和关闭三次，最后保持关闭；重新启动应用，确认图标仍默认关闭。
5. 在开关开启时尝试通过 Apple 菜单手动睡眠或锁屏；完成后唤醒并关闭开关。

输入：工具栏显示器图标的开启/关闭操作、一个已知的短系统空闲息屏时长，以及手动睡眠或锁屏操作。

预期输出：

- 默认关闭；启用后图标状态清楚可辨，系统在超过空闲时间时不会仅因空闲关闭显示器。
- 关闭后系统恢复原有的空闲显示器息屏行为；重复切换不导致卡死、崩溃或持续阻止息屏。
- 重启应用后开关不保留为开启；采集的开始、暂停、结束和悬浮字幕开关均不自动改变防息屏状态。
- 手动睡眠、锁屏、合盖、关机不被此开关阻止。

记录附加字段：系统设置的空闲时间、开启/关闭后的观察时间和屏幕结果、三次快速切换结果、重启后的状态，以及手动睡眠或锁屏结果。

### MAN-607 从历史记录续录（必测）

### MAN-100 阿里云实时原文与密钥存储（必测）

### MAN-102 Debug 与 Release 本机配置隔离（必测）

- Release 不显示 Debug 创建的课堂记录，也不复用 Debug 的 API Key 或地域；重新启动 Debug 后同样不显示 Release 新建的记录。
- 若 Release `Sessions.json` 格式无效，应用明确提示其完整文件路径，且不自动移动、删除或修改该文件，便于手动调查问题。

记录附加字段：两个目录的实际路径、两边各自可见的课堂记录数量、配置值是否交叉、无效文件报错中的路径，以及 Release 重启后的记录数量。

### MAN-301 主窗口聚焦字幕流（必测）

前置条件：MAN-100 已通过；主窗口处于正常大小，已开始会话。准备至少 6 条可断句的短句、1 条会换行的长句和其中一条的中文译文。

操作：

1. 连续输入至少 6 条短句，观察每一条成为最新字幕时的滚动和字号变化。

3. 使用 `A-` 和 `A+` 各两次，再连续输入两条短句。
4. 在字幕区手动向上滚动查看旧字幕，然后向下滚动；继续产生一条新字幕。

输入：6 条以上短句、1 条长句、至少 1 条迟到返回的译文，以及字号调整操作。

预期输出：

- 正在识别时，上一条已确认断句居中对齐并明显放大；若服务端同时保留多条临时识别文本，主窗口只显示最新的一条，且位于确认文本下方。不得在两者之间出现单个字符或其他过期临时行。没有已确认断句时，最新临时文本正常显示且不被放大。
- 已确认的历史字幕保持正常大小和清晰度，可阅读和选择复制；不出现阶梯式淡化。
- 临时原文新增或修订时以短暂的淡入和轻微上移动画更新，不突然跳出；新断句到达时视图以平滑的单次动画将阅读焦点移到该断句，不出现明显跳动、闪白或持续来回滚动。
- 临时原文确认、长原文和迟到译文到达后，当前已确认行均重新保持居中；长原文和译文自动换行且居中显示，不截断、不重叠，也不会把视图拉离当前行。
- 当前字幕下方保留明显空白，阅读不会紧贴窗口底边；调整字号后该空白、居中对齐与自动跟随均继续生效。
- 手动查看旧内容后，新字幕到达时自动回到最新聚焦行。

记录附加字段：窗口尺寸、字号、是否观察到跳动或截断、长句原文和译文是否完整显示。

### MAN-400 悬浮字幕窗口（必测）

前置条件：MAN-200 已通过；主窗口已有至少 4 条已确认字幕，其中至少 2 条已有译文；另有一条临时原文。准备一条足以换行的长句。

记录附加字段：显示器数量、是否覆盖全屏应用、窗口缩放结果、三个显示模式观察结果、键盘焦点实际所在应用、长文本换行结果、任何空白或尺寸异常状态。
